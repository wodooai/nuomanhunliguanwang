# 诺漫婚礼案例网站

当前官网：https://nuomanhunli.cn

## 当前权限（2026-09-29 已上线）

- 未注册访客和平台普通用户都属于外部，只能看首页资料和压缩案例小图。点击案例会进入平台用户注册 / 登录说明，注册本身不开放详情。
- 管理员在“用户与合伙人”中输入完整手机号，查找已注册用户、填写仅管理员可见的备注，并提拔为内部合伙人。
- 合伙人可浏览所有案例详情及大图，最多发布 30 个自己的案例，只能编辑或删除自己发布的案例。没有归属字段的历史案例属于平台。
- 管理员保留案例管理权限，并独占官网客服留言查看权限。
- 网站不提供大图直接下载、付费会员、订阅、推荐奖励设置或接口。旧订单和奖励数据仍留在历史 `data/members.json` 中，未删除。

## 案例与图片

- 新增或更新的每个案例最多 12 张图；编辑界面和服务端同时拦截超额。线上有 2 个历史案例原本超过 12 张（最多 15 张），未自动删除旧图；管理员下次编辑时需自行选定保留图片后保存。
- 首页封面从原图生成最长边 640 像素、质量 72 的 WebP 小图，存于 `data/thumbs/`。线上现有 95 张封面已预生成，总量约 3.36 MB。详情图仍由内部账号查看。
- 上传图片前使用本地 Tesseract 中英文 OCR 检测电话、联系方式、地址和明显商家名称；案例标题、介绍和价格文字也会检查。命中时拒绝，识别组件不可用时暂停图片上传。OCR 无法保证识别所有水印或变体，仍需人工审核可疑内容。
- 右下角“联系官网客服”提供文字留言，保存在 `data/support-messages.json`；只有管理员能读取全部留言。

## 运行与部署

Node.js 24+；在本目录执行 `npm ci` 后用 `npm start` 启动。图片文字识别还需要 Tesseract 及 `chi_sim`、`eng` 语言包。凭据按当前工作区规则从项目根 `.env`、`F:\workspace\.env` 读取；线上沿用 `/opt/nuomanhunli/.codex/.env`。不要提交凭据或 `data/`。

服务部署于阿里云 ECS 的 `/opt/nuomanhunli`，由 systemd 服务 `nuomanhunli` 运行；Nginx 转发到 `127.0.0.1:4188`。线上 `data/` 是持久化业务资料，更新代码时不能用本地旧数据覆盖。发布和验证细节见 [上线状态.md](./上线状态.md)。

## 邮箱找回与可迁移会员备份

- 注册需填写姓名、手机号、邮箱以及两次一致的至少 8 位密码。邮箱验证后才可用于找回密码；忘记密码必须收取邮箱验证码，不允许仅凭邮箱地址重设。验证码 10 分钟有效，最多输错 5 次；重设后旧登录令牌失效。
- 邮件发送需在运行环境配置 `NUOMAN_SMTP_HOST`、`NUOMAN_SMTP_PORT`、`NUOMAN_SMTP_USER`、`NUOMAN_SMTP_PASSWORD`（邮箱 SMTP 授权码）及 `NUOMAN_SMTP_FROM`。未配置时注册和登录仍可用，但邮箱验证与找回会明确提示未开通。不要把授权码放入代码或此文档。
- 2026-09-29 已配置线上 QQ SMTP：发信测试成功，`/api/member/email-status` 返回 `ready:true`。本机授权码来源是 `F:\workspace\.env` 的 `shouquanma`，线上服务凭据存于 `/opt/nuomanhunli/.codex/.env`。仍需在网页完成一次真实邮箱验证码收件验收。
- 飞书多维表格自动备份需配置 `NUOMAN_FEISHU_APP_ID`、`NUOMAN_FEISHU_APP_SECRET`、`NUOMAN_FEISHU_BASE_TOKEN`、`NUOMAN_FEISHU_TABLE_ID`，并授权该应用编辑目标 Base。配置完成后，服务启动时、会员资料变化时和每 5 分钟核对同步；失败后保留本地资料并重试。
- 2026-09-29 已在线上配置飞书凭据并启用同步。服务器实表核对返回 `enabled:true, created:0, updated:0`，表示当时的会员记录与多维表格一致；新注册、密码或角色及管理员备注变化会触发同步。线上凭据文件在 `/opt/nuomanhunli/.codex/.env`，原文件备份为 `.env.before-feishu-20260929`。
- 目标 Base 名称为“诺漫婚礼策划官网会员信息”，表字段为“用户ID、姓名、账号（手机号）、邮箱、邮箱已验证、用户属性、密码摘要、密码盐值、密码算法、注册时间、管理员备注”。密码摘要和盐值是原密码校验所需的迁移资料，不是明文密码，Base 应仅限管理员访问，不得公开分享。
- 新网站恢复登录时，导入这些字段，并按“密码算法”标识使用 Node.js `crypto.scryptSync(password, salt, 32).toString('hex')` 校验用户输入。账号、密码摘要与盐值须成套恢复；新网站不会仅凭拿到表格就自动支持登录。建议恢复后引导用户逐步更换新密码。
